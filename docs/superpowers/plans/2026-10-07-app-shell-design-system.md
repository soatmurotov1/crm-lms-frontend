**Goal:** Ship a viewport-efficient Auto Maktab shell, icon-only collapsed rail, unified slate/technology-blue theme, and one design-system board rendered in Storybook and an owner/dev-only app route.

**Architecture:** Keep `src/index.css` as the frontend token authority and let existing primitives inherit the new palette. Build one presentational `DesignSystemBoard` consumed by both a file-based route and Storybook. Change only the active app shell/sidebar, route/navigation/i18n contracts, board, and directly related tests.

**Tech Stack:** React 19, TypeScript 6, Vite 8, Tailwind CSS 4, TanStack Router, Radix UI, Phosphor Icons, Storybook 10, Vitest/jsdom.

**Spec:** `docs/superpowers/specs/2026-10-07-app-shell-design-system-design.md`

## Global Constraints

- Preserve business workflows, API calls, backend contracts, existing copy outside new design-system labels, mobile drawer behavior, onboarding behavior, and fleet-map full-bleed behavior.
- Keep Manrope for UI text and JetBrains Mono for figures, dates, codes, and token labels.
- Use deep slate/gray surfaces and a restrained technology-blue primary across app and Storybook; keep success, warning, destructive, and information roles distinct.
- Normal pages use 8px small-screen and 12px desktop outer gutters with no centered maximum-width cap.
- Collapsed desktop sidebar is 56px and visually icon-only; accessible names, titles/tooltips, active state, flyouts, keyboard behavior, and expanded/mobile labels remain.
- `/design-system` is guarded by `manageUsers`; the same board component renders in Storybook.
- Do not edit `src/routeTree.gen.ts` manually.
- Do not add dependencies or modify `@autodrive/design-tokens`.
- Commit once per wave on the owner's instruction; never push, open a PR, or merge.
- One implementer owns all code changes. At least two independent reviewers only report bugs and reasons the code fails; reviewers never edit.
